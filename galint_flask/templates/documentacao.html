1 Autenticação e Controle de Acesso

Rota: /login

Funcionamento:

  • Sistema utiliza Flask-Login para gerenciar sessões
  • Senhas armazenadas com hash seguro via Werkzeug
  • Dois níveis de acesso: Admin e Usuário Padrão
  • Admins podem: criar backups, restaurar, gerenciar usuários, autorizar descartes
  • Usuários padrão: visualização e registro de movimentações básicas

Fluxo de Dados:

  1. Usuário insere nome de usuário e senha
  2. Sistema valida credenciais no banco de dados (tabela users)
  3. Se válido, cria sessão e redireciona para dashboard
  4. Caso contrário, exibe mensagem de erro

2 Dashboard e Visualização

Rota: / (página inicial)

Funcionamento:

  • Exibe resumo do inventário agrupado por categoria
  • Cada categoria mostra: total de itens, quantidade em estoque, alertas de estoque baixo
  • Cards coloridos com ícones Bootstrap Icons
  • Dados atualizados conforme movimentações registradas

Fluxo de Dados:

  1. Sistema consulta tabela inventory_items
  2. Agrupa itens por categoria
  3. Calcula totais, médias e identifica itens abaixo do estoque mínimo
  4. Renderiza template dashboard/index.html com dados processados
Nova Funcionalidade: Dashboard pode ser compartilhado via Rede Galint com stakeholders externos usando link protegido por token.

3 Gestão de Inventário

Rotas: /inventario, /inventario/novo, /inventario/<id>/editar

Funcionamento:

  • Cadastro completo de itens com campos: descrição, categoria, localização, marca/fabricante, unidade, estoque mínimo
  • Listagem com filtros por categoria e busca textual
  • Edição e exclusão de itens existentes
  • Validação de dados antes de salvar

Fluxo de Dados:

  1. Usuário preenche formulário em /inventario/novo
  2. Sistema valida campos obrigatórios (descrição, categoria, unidade)
  3. Dados são salvos na tabela inventory_items via SQLAlchemy
  4. Sistema redireciona para listagem com mensagem de sucesso
  5. Para edição, carrega item existente e atualiza campos modificados
Campos do Modelo: id descricao categoria localizacao marca unidade quantidade estoque_minimo tipo_id

4 Movimentações (Entrada/Saída)

Rotas: /movimentos, /movimentos/entrada/page, /movimentos/saida/page

Funcionamento:

Entrada (Devolução):
  • Registra devoluções de itens ao estoque
  • Aumenta quantidade disponível do item
  • Campos: item, quantidade, observação
  • Grava na tabela entradas
Saída:
  • Registra retiradas de itens do estoque
  • Diminui quantidade disponível do item
  • Campos: item, quantidade, observação/anotações (rastreabilidade)
  • Grava na tabela saidas
  • Nova funcionalidade: Suporte a cálculo por frações para produtos líquidos

Fluxo de Dados:

  1. Usuário seleciona item do inventário (autocomplete ou dropdown)
  2. Insere quantidade e observação
  3. Sistema valida se quantidade disponível é suficiente (para saídas)
  4. Atualiza inventory_items.quantidade (+/- conforme operação)
  5. Registra movimentação na tabela correspondente (entradas ou saidas)
  6. Exibe confirmação e atualiza dashboard automaticamente

5 Cálculo por Frações (Produtos Líquidos)

Módulo: liquid-fractions.js + saida.mako

Funcionamento:

  • Interface dedicada para calcular quantidades de produtos líquidos em frações (galões, latas, baldes)
  • Suporta 8 tipos de produtos: Massa Acrílica, Tinta para Piso, Tinta Asfáltica, Tinta Epóxi, Tinta Acrílica, Resina Multiuso, Esmalte e Impermeabilizante
  • Frações disponíveis: 1/4, 1/2, 3/4, 1 (galão/lata/balde completo)
  • Modo Automático: Detecta produto selecionado e preenche unidade automaticamente
  • Modo Manual: Permite cálculo sem selecionar item do inventário (usando apenas tipo de produto)

Fluxo de Dados:

  1. Usuário ativa switch "Calcular por Frações" na página de saída
  2. Seleciona tipo de produto (ex: Tinta Acrílica)
  3. Sistema exibe a unidade padrão (litro ou quilo)
  4. Usuário insere capacidade do recipiente (ex: 18 litros)
  5. Clica em botão de fração desejada (ex: 1/2)
  6. JavaScript calcula:
    • Usado: capacidade × fração (na unidade principal)
    • Restante: capacidade - usado (na mesma unidade)
  7. Valores calculados preenchem campos de resultado (somente leitura)
  8. Ao desativar switch, campos são limpos e formulário volta ao padrão
Exemplo Prático: Para 1/2 galão de Tinta Acrílica (18L):
  • Litros utilizados: 9L (18 × 0.5)
  • Restante no galão: 9L
Tipos de Produtos Suportados: Massa Acrílica Tinta para Piso Tinta Asfáltica Tinta Epóxi Tinta Acrílica Resina Multiuso Esmalte Impermeabilizante

6 Notas Fiscais

Rota: /nf

Funcionamento:

  • Registro de documentos fiscais de entrada de mercadorias
  • Campos: número NF, fornecedor, data de emissão, valor (opcional)
  • Listagem com busca e filtros
  • Vinculação opcional com itens do inventário

Fluxo de Dados:

  1. Usuário acessa formulário de nova nota fiscal
  2. Preenche dados obrigatórios (número, fornecedor, data)
  3. Sistema salva na tabela notas_fiscais
  4. Nota fica disponível para consulta e auditoria

7 Materiais Avariados e Descarte

Rotas: /inventario-materiais, /inventario-materiais/avariados

Funcionamento:

Registro de Avariados:
  • Associa material danificado à saída original
  • Campos: item, quantidade avariada, motivo, observações
  • Grava na tabela materiais_avariados
  • Mantém histórico completo de danos
Relatório de Descarte:
  • Editor de texto rico estilo Word (Quill Editor)
  • Formatação completa: negrito, itálico, listas, títulos, cores
  • Geração de documento .docx para assinatura do gerente
  • Download automático do arquivo

Fluxo de Dados:

  1. Usuário registra material avariado vinculado a uma saída específica
  2. Sistema armazena registro com timestamp e responsável
  3. Acessa página de avariados e clica em "Criar Relatório de Descarte"
  4. Editor Quill carrega com template padrão (pode ser editado)
  5. Usuário formata texto conforme necessário
  6. Clica em "Gerar Documento"
  7. Backend usa python-docx para converter HTML → .docx
  8. Arquivo é enviado para download com nome relatorio_descarte_[timestamp].docx
  9. Registro é salvo na tabela descarte_autorizacoes
Controle de Segurança: Apenas administradores podem autorizar descartes finais e gerar documentos oficiais.

8 Backup e Restauração

Rota: /configuracoes

Funcionamento:

  • Suporte para PostgreSQL
  • Backup manual via interface web (apenas admins)
  • Opção de backup automático agendado (via CLI)
  • Restauração seletiva de backups anteriores
  • Gestão de backups: listagem, exclusão, limpeza automática de antigos

Fluxo de Dados:

Criação de Backup:
  1. Admin acessa página de configurações
  2. Clica em "Criar Backup"
  3. Sistema identifica tipo de banco configurado:
    • PostgreSQL: Executa pg_dump via subprocess
  4. Arquivo salvo com timestamp: galint_backup_YYYYMMDD_HHMMSS.sql
  5. Flash message confirma sucesso
Restauração:
  1. Admin seleciona backup da lista
  2. Confirma ação (alerta de sobrescrita de dados)
  3. Sistema para aplicação temporariamente
  4. Restaura banco de dados:
    • PostgreSQL: Executa psql para importar dump
  5. Reinicia aplicação com dados restaurados
Atenção: Restaurar backup sobrescreve todos os dados atuais. Certifique-se de criar um backup antes de restaurar.

9 Rede Galint (Compartilhamento Público)

Rota: /rede-galint?token=<TOKEN>

Funcionamento:

  • Permite compartilhar dashboard com stakeholders externos (gerentes, auditores, fornecedores)
  • Acesso protegido por token de segurança configurado em variável de ambiente
  • Não requer login, apenas conhecimento do link com token
  • Visualização somente leitura do dashboard
  • Sem acesso a funcionalidades de edição ou dados sensíveis

Fluxo de Dados:

  1. Admin configura DASHBOARD_SHARE_TOKEN no arquivo .env
  2. Acessa página de configurações e copia link da Rede Galint
  3. Compartilha link com stakeholder externo
  4. Stakeholder acessa URL: https://dominio.com/rede-galint?token=ABC123
  5. Sistema valida token contra configuração
  6. Se válido, renderiza dashboard público (sem sidebar, sem opções de edição)
  7. Se inválido, retorna erro 403 (Acesso Negado)
Caso de Uso: Gerente remoto pode acompanhar status do estoque sem precisar de conta no sistema.

10 Gestão de Usuários

Rota: /usuarios

Funcionamento:

  • Apenas administradores podem gerenciar usuários
  • Criação de novos usuários com nome, username, senha e nível de acesso
  • Edição de usuários existentes (alterar senha, promover/rebaixar admin)
  • Exclusão de usuários (com validação para não excluir si próprio)
  • Listagem com cards coloridos mostrando setor de cada usuário

Fluxo de Dados:

  1. Admin acessa /usuarios
  2. Clica em "Novo Usuário"
  3. Preenche formulário (nome completo, username único, senha forte, checkbox admin)
  4. Sistema valida:
    • Username não duplicado
    • Senha com mínimo 6 caracteres
    • Nome completo preenchido
  5. Hash da senha é gerado via generate_password_hash()
  6. Usuário salvo na tabela users
  7. Listagem atualizada com novo card de usuário
Campos do Modelo User: id username password_hash name is_admin setor

Stack Tecnológico Completo

Backend:
  • Flask 3.0.3: Framework web Python
  • SQLAlchemy: ORM para banco de dados
  • Flask-Login: Gerenciamento de sessões
  • Werkzeug: Hash de senhas e utilitários
  • python-docx: Geração de documentos Word
  • Mako 1.3.5: Template engine para páginas dinâmicas
Frontend:
  • Bootstrap 5.3.3: Framework CSS responsivo
  • Bootstrap Icons: Biblioteca de ícones
  • Quill Editor: Editor WYSIWYG para relatórios
  • JavaScript Vanilla: Calculadora de frações, formulários dinâmicos
Banco de Dados:
  • PostgreSQL: Banco principal (produção)
